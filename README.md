# learning-loops

학습 노트를 휴대폰 브라우저에서 읽고, 장마다 읽음 체크 → 그 장 문제로 테스트 → 날짜를 두고 재점검 → 숙달까지 관리하는 정적 사이트다. 서버·빌드 없이 GitHub Pages 에 그대로 올린다. 디자인 시스템은 [Framework7](https://github.com/framework7io/framework7) 9.3.0(MIT)의 CSS 만 쓴다.

## 화면

| 주소 | 화면 |
|---|---|
| `#/` · `#/today` | 오늘 — ① 오늘 할 일(일정상 오늘까지 장·밀린 장 「M/D 밀림」·재점검 대기 수·「다시 볼 항목 n」(복습 화면으로), 채움 버튼 하나: 일정 장 → 재점검 → 이어 읽기 순) ② 이번 주 학습량(요일별 읽은 항목·푼 문항 막대, 연속 학습일 — 장 1개를 다 읽었거나 문항 3개를 푼 날) ③ 주제별 진행(진행 % = 테스트 통과 이상 장 / 전체 장, 일정 있는 주제만 「일정대로 / N장 밀림 / N장 앞섬 / M/D 시작」) ④ 다가오는 7일 재점검 |
| `#/topics` | 주제 — 주제 카드(진행 막대 · 「다음: <장 ID>」 이어 읽기). 채움 버튼은 하나 — 오늘 일정 주제(오늘까지 잡힌 안 끝난 장으로), 없으면 가장 최근에 읽은 주제 |
| `#/t/<주제>` | 목차 — 부별 접기, 장 단계(○ 읽기 전 → ◔ 읽는 중 → ◑ 읽음 → ◕ 테스트 통과 → ● 숙달), 「지금 장으로」, 다시 볼 항목이 있는 장 행에 「질문 답 n · 업데이트 n」. 일정이 있으면 부 머리 「N장 · M/D부터」, 장 행에 일정 날짜(안 끝난 장이 날짜를 넘기면 빨강 「M/D 밀림」), 범례 줄 끝에 날짜·밀림 설명 |
| `#/t/<주제>/c/<장>` | 장 — 항목(`## ` 절) 읽음 체크(다시 볼 항목은 「업데이트 있음」·「질문 답 있음」), 항목을 모두 읽으면 그 장 테스트 |
| `#/t/<주제>/i/<항목>` | 항목 읽기 — 위 「n / m」 줄(장 안 위치·읽음 막대)을 누르면 장 안 항목 목록 시트, 아래 바 「‹ 이전 · 읽음 ✓ · 다음 ›」. 읽음 체크하면 다음 항목, 장 마지막 항목이면 장 완료. 제목 위 「업데이트 있음」(읽은 뒤 바뀜)·「질문 답 있음」(마지막 질문 뒤 바뀜, 읽음 여부 상관없음) — 아래 바 「다시 읽음 표시」를 누르면 읽음 시각이 지금으로 바뀌어 사라짐. 맨 아래 「모르는 것」: 여러 줄 질문 추가·목록(시각)·지우기 |
| `#/t/<주제>/done/<장>` | 장 완료 — 그 장 테스트 · 다음 장 읽기 |
| `#/review` | 복습 「전체」 — 주제 칩(「전체 n」·주제 이름 n, n = 오늘 재점검 대기 수, 가로로 밀어 보기), 숫자 3줄(오늘 재점검·새 문제·아직 다 읽지 않은 장), 채움 버튼 하나(모든 주제를 한 회차로), 「오늘 재점검 내역」 장별 목록, 「다시 볼 항목 n」 목록(누르면 그 항목), 재점검 간격 안내 한 줄 |
| `#/t/<주제>/review` | 복습 — 칩에서 고른 주제만(화면 구성은 「전체」와 같음), 선택지 문항은 자동 채점 |
| `#/settings` · `#/t/<주제>/log` | 설정 — 동기화 설정, 결과 보내기(GitHub 비공개 저장소)·결과 요약 보기·복사·백업 내보내기·가져오기(log 는 그 주제를 고른 설정) |

아래 탭 4개(오늘 · 주제 · 복습 · 설정)를 모든 화면에 고정하고, 「복습」 탭에 모든 주제의 오늘 재점검 수 배지를 단다. 테스트 회차 중에는 아래 탭을 숨기고 위 막대에 「그만두기」만 둔다. 위 막대 가운데 경로(예: `계정·인증 학습·구현 ▾ › AUT03`)의 주제 이름을 누르면 주제 바꾸기 시트가 올라온다.

## 주제 더하기

원본은 옵시디언 노트이고 `topics/` 는 변환 결과다. `topics/` 의 JSON 은 손으로 고치지 않는다.

```bash
node tools/build_topic_from_obsidian_notes.mjs "<입구 노트>.md" [--deny-file <금지어 파일>]
```

- 입구 노트 앞머리 `learning_key`(대문자 3글자)·`learning_slug`(영문 kebab, 주소), 선택 `learning_summary`·`pages_exclude`(빼고 올릴 절 이름)·`pages_rename`(`옛 절=보일 제목`, 화면 제목만 바뀌고 항목 ID 는 그대로)·`pages_replace`(`옛 말=보일 말`, 노트 원문 전체에서 바꾸고 옛 말은 금지어로 검사 — 항목 ID 도 바뀌어 그 항목 진행은 처음부터). 앞머리가 없으면 같은 이름의 옵션(`--key`·`--slug`·`--exclude`·`--rename`·`--replace`)으로 준다.
- 본문의 볼트 세션·결정 번호(`S294`·`S1000043-D1` 꼴)는 걷어 내거나 "내부 결정"·"내부 기록" 으로 바꾼다. 해시 방식 이름 `S256`·`S384`·`S512` 는 그대로 둔다.
- 입구 `## 목차` 의 `[[<KEY>## …]]` 목록 줄 순서가 장 순서, 그 위 `### ` 머리가 부다.
- 장 노트 `## ` 절이 읽음 항목(ID `<장>#<절 제목>`)이다. `검수`·`출처`·`이해 확인 질문` 절은 항목이 아니다.
- 문항은 `## 이해 확인 질문` 안 `> [!question]- <장>-Q01 질문` callout 이고, 답은 정답 → `이유:` → `단서:` 순서다.
- 선택지 문항은 callout 안에 `선택지: 보기 | **정답** | 보기` 줄을 둔다(보기 2개 이상, 굵게 한 정답 1개 — 아니면 exit 1). 사이트가 보기 순서를 섞고 자동 채점한다. 이 줄이 없으면 정답을 보고 직접 채점한다.
- 입구 노트의 `## 학습 일정` 절(선택)은 날짜 목록 줄 하나가 하루다. 줄에서 날짜와 `<KEY>` 장 ID 만 읽어 `index.json` 에 `schedule: [{ "date": "YYYY-MM-DD", "chapters": ["AUT01", "AUT02"] }]` 로 넣는다. 절이 없으면 `schedule` 이 없고 사이트는 일정 없이 진행만 보인다.
  ```markdown
  ## 학습 일정
  설명 문단은 읽지 않는다.
  - [ ] 11/19(목) — AUT01 · AUT02
  - [x] 11/20(금) — AUT03 · AUT04 + [[다른 노트]]
  - 2027-01-04 — AUT05
  ```
  - 날짜는 `M/D`(요일 `(목)` 은 선택) 또는 `YYYY-MM-DD`. 연도 없는 날짜의 해: 첫 줄은 요일이 있으면 변환하는 날에 가장 가까운 해(앞뒤 1년 중), 없으면 변환하는 날의 해. 둘째 줄부터는 앞 줄의 해(앞 줄보다 달이 줄면 다음 해). 그 해에서 요일이 맞지 않거나(요일 오타를 다른 해로 옮기지 않음) 없는 날(`2/30`)이면 exit 1.
  - 체크 상자(`[ ]`·`[x]`)는 읽지 않는다. 밀림·앞섬은 사이트가 진행 상태로 센다(장이 「테스트 통과」 이상, 문항이 없는 장은 「읽음」이면 끝남).
  - 목차에 없는 장 ID 와 장 ID 가 없는 줄은 뺀다. 같은 장이 두 번 나오면 앞 날짜를 쓴다.
- 항목 `updated: "YYYY-MM-DD"`(선택 칸): 변환기가 이전 빌드의 `topics/<주제>/<장>.json` 과 같은 항목 ID 의 본문 html 을 비교해(태그 사이·연속 공백은 무시) 바뀌었거나 그 장에 새로 생긴 항목에 빌드 날짜를 넣고, 같으면 이전 값을 그대로 둔다(없으면 넣지 않음). 이전 장 파일이 없으면(첫 빌드·새 장) 넣지 않는다. 날짜는 `--date YYYY-MM-DD` 로 바꿀 수 있다(기본 변환하는 날, 로컬). 사이트는 그날 00:00 이 읽음 시각보다 뒤면 「업데이트 있음」, 마지막 질문 시각보다 뒤면 「질문 답 있음」으로 보인다 — 날짜 단위라 읽거나 물은 그날 고친 내용은 표시되지 않는다. 변환 결과 줄 `"updated": n` = 이번 빌드 날짜가 붙은 항목 수.
- 출력에 비밀값 꼴(개인 키·AWS access key·토큰·IP·AWS 계정 번호·내부 URL)이나 금지어 파일(줄마다 한 단어)의 말이 나오면 쓰지 않고 exit 1 로 끝난다. 명세 절 번호(`§3.1.1.2`)·문서용 예시 IP 대역·`localhost` 는 걸리지 않는다. 교재 예시 IP·호스트는 입구 노트 앞머리 `pages_allow_example_ip: true` 나 `--allow-example-ip 1`(또는 `true`)일 때만 통과한다 — `0`·`false` 는 끔.

지금 올린 주제를 다시 만드는 명령(원본 노트가 있는 기기에서 — 노트는 비공개 저장소로 기기 사이에 옮겨진다):

| 주제 | 명령 |
|---|---|
| `learning-science` | `node tools/build_topic_from_obsidian_notes.mjs "examples/learning-science/학습 과학 기초.md"` |
| `account-auth` | `node tools/build_topic_from_obsidian_notes.mjs "<노트 폴더>/계정·인증 학습·구현/계정·인증 학습·구현.md" --key AUT --slug account-auth --rename "LP 포털·어드민 적용=적용 사례 — B2B 포털·어드민"` |

절 제목이나 문항 ID 를 바꾸면 그 항목·문항의 진행 상태가 처음으로 돌아간다(상태가 ID 로 저장됨).

## 공개 범위

저장소와 사이트는 공개다. 실제 적용 사례를 "이런 방식은 이런 경우에 맞다" 수준으로 담는 것은 괜찮지만, 비밀값·키·토큰·IP·AWS 계정 번호·내부 URL 은 올리지 않는다(변환기가 막음). 학습 진행 상태는 각 기기 브라우저 `localStorage`(`ll2:<주제>`)에 `{ read, unread, cards, log, questions }` 로 저장된다 — `questions` 는 항목 ID 마다 「모르는 것」 질문 `[{ t, text }]`(t = 적은 시각 ms, 지운 질문은 `text: ""`·`del: 지운 시각` 으로 남겨 기기 사이에 합쳐도 되살아나지 않음)이고, 옛 저장값에 없으면 빈 값으로 채운다. 기기 사이에는 항목마다 `t` 로 합집합해 시각 순으로 합치고, 「결과 보내기」 요약 끝에 「모르는 것 n건」 절(항목 ID·제목·시각·글)로 실린다. 기록 화면에서 동기화를 켜면 진행 상태와 결과를 사용자가 넣은 **비공개** 저장소(기본 `stepby-unicorn/learning-loops-data`)에 GitHub API 로 올린다 — 설정할 때 저장소가 비공개이고 토큰에 쓰기 권한이 있는지 확인하고, 아니면 켜지지 않는다. 토큰(fine-grained PAT, 그 저장소 하나·Contents 읽기 쓰기)은 그 기기 브라우저 `localStorage`(`ll2-sync`)에만 저장되고 이 저장소에는 들어가지 않는다.

## 재점검 일정

새 문항은 회차 안에서 1번 맞히면 상자 1로 가고(틀리면 회차 끝에 1번 더 나오고, 또 틀리면 그 회차의 「두 번 틀린 문제」 로 남김), 그 뒤 1·3·7·21·60·180일 뒤 다시 점검한다(상자 4 = 숙달, 마지막 상자 뒤로는 180일마다). 틀리면 상자 1로 돌아간다. 바꿀 때는 `assets/engine.js` 의 `SCHEDULE` 과 `tests/schedule.test.js` 를 같이 고친다.
